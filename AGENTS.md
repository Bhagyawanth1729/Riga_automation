# Riga — Agent Operating Manual

Source of truth: *Riga STEM Guidelines V1.3* (16 July 2026), Snorkel Expert Platform. Official PDF: `docs/guidelines/Riga-Project-Guidelines-V1.3.pdf`.

You are helping one expert contractor **author and review original Physics / Chemistry / Biology problems** that survive automated difficulty checks and human Quality Review. LLM assistance is allowed. Templated spam, plagiarism, and speed-over-quality work are dismissal offenses.

**Goal of every task file:** a single original problem a working PhD in that field could have written for a qualifying exam, with a closed unique answer, a hand-checkable solution, and formatting that matches the Snorkel UI exactly.

Do not invent platform rules. If a rule is not in `docs/guidelines/` or this file, do not guess.

---

## What this repository is

A local authoring desk. You draft here, validate here, then the user pastes fields into:

- `EK_Riga_Production / Riga Submission`
- `EK_Riga_Production / Riga Review`

You never submit to Snorkel yourself. You never scrape other experts' problems. You never clone IChO / IPhO / USABO / textbook end-of-chapter items with the numbers swapped. You never clone the gold Harned-cell skeleton.

How to start on the platform: Expert Platform → My Projects → search `Riga` → blue **Start**.

## Default workflow (Submission)

1. Pick **one** field, domain, and subdomain from `data/catalogs/domains.json`. If `data/catalogs/platform_domains.json` lists a live dropdown for that field, the domain **must** be on that list (Biology on this account does not include Genetics and Genomics). Domain is the *central subject*, not a technique that appears in one solution.
2. Design the **answer first** in `scratch.md`. The answer must be a single checkable object.
3. Invent a setup that forces a real mistake a frontier model makes: a dropped activity, a wrong $n$, a misapplied approximation, an identical-particle sign, a phase convention, a neglected junction, a mapping-function choice. Not a word puzzle. Not a trick of ambiguous English.
4. Write the prompt so a competent human can solve it with only the text plus ordinary STEM knowledge. Include every constant, table row, and convention that would otherwise live in a paper.
5. Write **at least three substantial steps**. Each step is one scientific move. No substeps. No "Step 2a".
6. Run `python3 scripts/qa_gate.py path/to/task.md` and fix every error.
7. Recompute every displayed equality yourself (hide the boxed line and redo the arithmetic). Set `independently_verified: true` only after that.
8. Run `python3 scripts/preflight.py path/to/task.md`. Promote with `python3 scripts/promote.py path/to/task.md ready`.
9. Emit paste fields with `python3 scripts/paste_ready.py path/to/task.md`.
10. User pastes into the left-pane prompt box and runs **both hard models**. At least one must miss **consistently**. Official Automated Difficulty requires **≤88% success on at least one of the two models**. "No Response was generated by the model" is not a miss — re-run.
11. User pastes the rest of the UI (see `docs/platform/ui-fields.md`), runs **In-App Evaluation** (mandatory; ignore the word optional), then **Automated Checks Only**.
12. Only after those checks are clean, route to **Quality Review**.

If the models solve it, do not add a riddle. Change the physics/chemistry/biology so the reasoning is actually harder.

## Acceptance bar (non-negotiable)

A submission is eligible for Accept only if **all** of the following hold.

### Prompt

- Original. Authored by a human expert (LLM help is permitted). Not from a contest, paper, dataset, or another expert. Not a paraphrase of a gold example in this repo.
- One question. Never parts (a)(b), never two independent asks glued together.
- Open method, **closed unique answer**. Equivalent forms are fine. `DNE` is not.
- Answer format is stated in the prompt (exact expression, variables allowed, rounding, units). If a decimal is required, the prompt must give the rounding rule; a model's rounding is not an error without that instruction.
- Self-contained. No "see Smith 2019". No missing symbol definitions. Tables and background live in the prompt.
- Requires multi-step reasoning, not recall of a named fact.
- Not a proof (`show that`, `prove`, `verify that`).
- Not guessable (MC, T/F, yes/no).
- Not a word puzzle, even if solvable with set theory.
- Not a computer-algebra slog. A scientific calculator is the ceiling.
- No shortcutting: the prompt must not leak the method in a sentence that makes the rest decorative.
- Makes sense in the chosen domain.
- `chemfig` is unsupported. `mhchem` (`\ce{}`) is supported.

### Solution

- Correct, and **each step is correct even if you hide the final answer**.
- Every nontrivial claim after "clearly / note that / it follows" has an argument. Prefer not to use those words at all.
- Every assumption that would change the number if dropped is stated and justified.
- Minimum 3 steps. Each step starts with `Step N`.
- Last step ends with exactly: `Final Answer: $\boxed{...}$`
- When a later step uses an earlier result, say `Step 2`, not "from earlier".
- No micro-steps, nested steps, or decorative asides that do not advance the answer.
- Notation is consistent across all steps.

### Answer field

- Matches the boxed value **exactly**.
- Wrapped in `$...$` only. **No** `\boxed`.
- If the prompt did not name units, the answer must.
- Uses only notation introduced in the prompt.

### Labels

- Domain / subdomain match the *subject*, with a three-sentence justification in the required shape (below).
- Problem type = what the final object *is*, not how you got there.
- Answer type = the written form of that object.
- Concepts: 1–5 short noun phrases, most important first.

## Domain justification (paste verbatim shape)

```
This problem involves <key elements>, which are part of <domain and subdomain>.
The problem also involves <additional elements>, which are part of <next-best domain and/or subdomain>.
However, <why the runner-up is not core, or is less advanced>.
```

Do not skip the runner-up. Reviewers use that sentence to test whether you understood the taxonomy.

### Official difficulty

Automated Checks Only reports model success rates. Acceptable difficulty: **at most 88% success on at least one of the two models**. A one-off miss is not enough. If models converge on a *different* number than yours, recompute before arguing.

Any later edit to Problem or Answer can change difficulty. Re-run.

## Voice: write like a specific scientist, not like a chatbot

Reviewers and originality checks punish **templated cadence** as hard as they punish wrong algebra. The Code of Conduct names "short, repetitive, or templated responses" as spam.

Write as if you are a named person:

- a condensed-matter experimentalist,
- a physical organic chemist,
- a quantitative geneticist,

who is setting a closed problem for a colleague. That person:

- opens with the system, not with "In this problem we will"
- uses the field's ordinary jargon without defining undergraduate words
- puts numbers in realistic experimental ranges
- states conventions the way a paper's Methods section does (standard states, gauge, ensemble, 5′→3′, IUPAC)
- varies sentence length
- never moralizes ("this demonstrates the power of the Nernst equation")
- never uses booster adjectives (robust, pivotal, tapestry, delve, leverage, comprehensive)

Forbidden tells are enforced by `scripts/check_voice.py`. If the gate flags a phrase, rewrite the sentence from scratch.

Each problem must have a different skeleton than the last one you wrote in this repo. If you catch yourself cloning the gold Harned-cell shape, stop and change the scientific object.

PDF example problems (Harned cell, perturbation theory, retrosynthesis, identical particles, linkage) are **inspiration only**. The PDF itself says they are not the LaTeX standard.

## How to stump models without cheating

Allowed: genuine applicability conditions, non-default standard states, coupled constraints, identical particles, activity vs concentration, when an approximation is illegal, unusual but stated sign conventions.

Forbidden: ambiguous English, hidden definitions, "gotcha" parsing, yes/no, riddles, contest chestnuts with the numbers changed, anything that is hard because the wording is bad.

If a human expert would call it unfair, it will be sent back as Guessable, Not Self-Contained, or Other.

## Final checklist (before Quality Review)

From the platform Final Checks:

- One and only one correct answer
- Spelling and grammar checked
- Solution steps independently verified
- Not plagiarized
- Appropriate LaTeX (`$...$` / `$$...$$`; never `\(...\)` / `\[...\]`)
- Answer box is the final answer only, wrapped in `$...$`, no `\boxed`

Local extras:

- `qa_gate.py` prints `PASS`
- `independently_verified: true`
- both hard models run; at least one misses consistently
- In-App LaTeX check run
- Automated Checks Only is green on difficulty

## Review mode

When the user is on `Riga Review`:

- You are not the author. Do not rewrite the problem or the answer.
- Light-edit only grammar, LaTeX, spelling, clarity in the **solution steps**.
- Solve the problem yourself. A matching final answer does not certify the steps.
- Difficulty: if it reached human review, assume the auto-check found it hard, unless it is *blatantly* trivial or a word-puzzle stump.
- Decision: Accept / Needs Revision / Reject.
- Reject is rare: spam, plagiarism, or total disregard of the rules. Rejections flag the submitter.
- Needs Revision requires **error categories** from `data/catalogs/error_categories.json` plus notes that name each category and tell the author exactly what to change. Test: if they did only what you wrote, would it accept?
- On Accept, fill disputable-claim justifications (up to 3) when a domain expert could argue, and answer **Are All Automated Checks Accurate?**
- Reviews take 20–30 minutes. Generic feedback is a reviewer violation.

Use `templates/review.md`.

### Error categories (must name them in revision notes)

Prompt: Not Self-Contained · Non-Unique Answer · Too Computational · Multi-Part Question · Guessable · Domain Beyond Project Scope

Answer and steps: Wrong Answer · Unjustified or Unsupported Claims · Unstated Assumption · Step Error

Any section: Major LaTeX or Formatting Issues · Major Grammar or Language Issues · Other

Minor LaTeX/grammar in steps: fix in review; do not send back for those alone.

## File contract

Every submission lives at `submissions/<lane>/<id>/task.md` with the frontmatter + section schema in `templates/task.md`.

Lanes: `drafts` → `ready` → `submitted` → `accepted` | `needs_revision` | `rejected`.

Each item: `task.md` (platform fields) + `scratch.md` (local solve) + `PASTE.md` (UI copy blocks).

`## Author Notes` never goes on the platform.

## Code of conduct (project)

Spam, plagiarism, a pattern of rejections, suspiciously low handling time, and hostile or recruiting behavior are fireable. Work slowly enough that every equality was actually recomputed. Do not manufacture volume.

Channels named in the PDF: `#ec-riga-reviews` for borderline review calls.
