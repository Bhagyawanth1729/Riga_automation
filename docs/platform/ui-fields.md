## A. Riga Submission

### Left pane — model stump test

| Control | What you type / click | Rule |
|---|---|---|
| UID | read-only | Ignore |
| Note | read-only | These models are a reference, not the official difficulty check. A model may miss once and still get it most of the time. You need a **consistent** miss. |
| `Enter your prompt here` | Full LaTeX problem | Same text you will paste as Problem (Prompt) |
| Arrow button | Run both hard models | Wait. Thinking models can take minutes. |
| Model replies | read-only | Wrong answer = useful. **No Response was generated by the model** = not a miss. Re-run and ping Snorkel if it keeps happening. |

Copy the prompt into the right pane with **Paste from Prompt** after you are happy with the stump test.

### Right pane — Problem Submission

| # | UI label | Input type | What goes in |
|---|---|---|---|
| 1 | Problem (Prompt) | Write / LaTeX Preview | The single self-contained problem. Tabs: Write, LaTeX Preview. Button: Paste from Prompt. |
| 2 | Domain | dropdown | Biology / Chemistry / Physics domain from the catalog. Biology: use `platform_domains.json` (Genetics and Genomics is **not** on this account). |
| 3 | Sub-domain | dropdown | Must sit under the chosen domain |
| 4 | Domain Explanation | text | Exactly three sentences in the required shape |
| 5 | Worked Solution | repeating Write / LaTeX boxes | Box 1, 2, 3, … Each body starts with `Step N`. Last box ends `Final Answer: $\boxed{...}$` |
| 6 | Answer | Write / LaTeX Preview | `$...$` only. No `\boxed`. Must match the boxed payload, units included if the prompt omitted them. |
| 7 | In-App Evaluation | button `Check Accuracy of LaTeX` | Header says optional. **Project says mandatory.** |
| 8 | Problem Type | dropdown | What the final object is (`data/catalogs/problem_types.json`) |
| 9 | Answer Type | dropdown | Written form of that object (`data/catalogs/answer_types.json`) |
| 10 | Solution Concepts | 1–5 short items | Noun phrases, most important first |
| 11 | Submission Routing | dropdown | `Automated Checks Only` first; `Quality Review` only when you believe it will accept |
| 12 | Submit | button | After every required field is filled |

### Domain Explanation shape (required)

```
This problem involves <description of the key elements of the problem>,
which are part of <domain and sub domain>.
The problem also involves <description of the additional elements of the problem>,
which are part of <other domain and/or sub domain>.
However, <explanation of why they’re not core to the problem or less advanced>.
```

### Routing outcomes

**Automated Checks Only** returns, while you can still edit:

- whether difficulty is acceptable (≤88% success on ≥1 of the two models)
- the full results of how the models solved the problem
- whether problem + solution are correct/complete
- whether solution steps have logical gaps or mathematical errors
- whether domain + justification are appropriate

Example difficulty panel:

- Result: sufficiently difficult (or not)
- Model 1 success rate
- Model 2 success rate
- Warning if models converge on a *different* number than yours — treat that as a red alarm and recompute

Any later edit to Problem or Answer can change difficulty. Re-run.

**Quality Review** sends the item to a human reviewer (20–30 min review). Select it only after Automated Checks Only is green **and** you still believe the science.

### Final Checks (platform)

- One and only one correct answer
- Spelling and grammar
- Independently verified solution steps
- Not plagiarized
- Appropriate LaTeX
- Answer box is `$...$` only, no `\boxed`

## B. Riga Review

Expected handling time: 20–30 minutes.

| # | UI label | Who fills it | Notes |
|---|---|---|---|
| 1 | Problem Submission | OA, reviewer may light-edit **steps only** | Problem, domain, steps, answer |
| 2 | Problem Type / Answer Type / Concepts | OA; reviewer may correct these | If you change them on Needs Revision, say so in the notes |
| 3 | Automated Difficulty and Quality Feedback | system | Read it. Do not re-litigate difficulty unless blatantly trivial or a wording trick. |
| 4 | Automated feedback (blue, left) | system | Possible issues. Use with #3. |
| 5 | AI-Generated Answers | system text; reviewer required | For each model: read the answer, mark Yes/No = equivalent to the OA answer |
| 6 | Review Decision | reviewer | Accept / Needs Revision / Reject |
| 7 | Justification of Disputable Claims | reviewer, on Accept | Up to 3. Each: claim / why an expert might object / why it is still justified. Skip if purely mechanical. |
| 8 | Are All Automated Checks Accurate? | reviewer, on Accept | Yes / No. If No, explain why the false positive does not block accept. |
| 9 | Error Categories | reviewer, on Needs Revision or Reject | Multi-select from the official list |
| 10 | Revision Notes / Rejection Notes | reviewer | Must name each selected category and give an actionable fix |

Reject only for spam, plagiarism, or total disregard of the rules. Rejections flag the submitter to Snorkel.

Reviewer test: *If the Original Author addressed everything in the revision notes, would it be acceptable on re-submission?* If not, write more.

## C. Paste order (submission)

Use `python3 scripts/paste_ready.py path/to/task.md`. Then:

1. Left prompt → run models
2. Paste from Prompt
3. Domain, sub-domain, justification
4. Steps (one box each)
5. Answer
6. Check Accuracy of LaTeX
7. Types + concepts
8. Automated Checks Only
9. Quality Review only after green difficulty **and** you still believe the science
